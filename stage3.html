    Stage 3 records each automation by hand, because Airtable's API does not return automations. The base's schema must already be ingested in Stage 1, so tables and fields can be chosen from lists.

    A Choose an automation

    An automation is recorded as its trigger, then its steps in the order they run. Conditional blocks (if / else if / else) and repeating groups hold further steps, and conditions can be nested groups of ALL / ANY. Each save creates a new version; earlier versions are never changed.

    Add actions, conditional blocks and repeating groups. A condition can read the trigger record or the record created, updated or found by an earlier step, so add the step it depends on above it first. Text supports bold, italic and links; use the buttons above each text box.

    C Documentation and rebuild report

    The Airtable report is the audit record. A Workfront Planning report shows the same automation with each Airtable field replaced by its target field from the field crosswalk, so a person can rebuild it as a Workfront Fusion scenario. It says plainly when a field has no mapping yet.
