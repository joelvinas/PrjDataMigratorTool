Calculated fields: preflight

Translates the Airtable formula fields of one table into Workfront Core calculated field expressions and reports what can and cannot be translated. The preflight only reads the schema and the crosswalks and saves its answer; it sends nothing to Workfront. Creating the fields and writing the expressions is a separate step, further down, that works from a run you approve.

A formula field is translated only when every field it reads has a target in the crosswalk (made on Core fields in bulk) and it has an approved Core name on Field names. Several formula fields that share one approved Core name become ONE Core field, placed on each form with that form's own expression. A calculated field gets the displayType CALC. The translations are provisional until each function has been tried in a sandbox.

Approval

Approving saves your initials, the time and the reason on the run. It sends nothing. If the schema or the crosswalk has changed since the run, approval is refused and a new preflight is needed.

Push to Workfront

Works from the approved run only. It creates each calculated field (an existing field with the same name and the right type is used instead, never an error), adds the new fields to the end of the custom form, keeping every field already on it exactly as it was, and only then writes the expressions. A formula that fails does not stop the others; press Retry to send only what is not done. Every call is logged. This is the one step that changes Workfront.
