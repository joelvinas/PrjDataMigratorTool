    Loads one table into Workfront Planning, one step at a time. Each step opens only when the one before is done, and a step that sends anything asks you to confirm the table, the stage and the Workspace ID first. Nothing is sent when this page opens; the only call it makes is one read of the Workspace to prove the token and Workspace ID work, and that unlocks the steps (the third green badge above). The stages (dev, uat, production) are the ones you define in config.json under workfront.planning, each with its own base_url, bearer_token and workspace_id; the Workspace name is fetched, not typed, and the token is never shown here. It uses the same code as loader.py (run, records, reset with --table), so a step done here and a step done from the command line leave the same record in the database.

    Running
    A cancel takes effect between items or batches, never in the middle of a call. Whatever was finished is kept, and a rerun carries on from there.

Anything blocked stops here: nothing below opens until it is fixed. Held items are skipped, not loaded. Reads only; nothing is sent.

    2. Create the record type and fields locked

    Creates this table's Planning record type, its fields and their select options (one table, like --table). A record type that one of its link fields points to is created empty so the link field can be built. Run the dry run first; it sends nothing. Each new Workfront ID is written to the database as it comes back, so a stop or a restart never creates anything twice.

    3. Records locked

    Loads this table's saved Airtable records (without their links) into its record type. The saved file is read in memory and each value is sent and forgotten: only record IDs, counts and statuses are shown or stored. A record Planning refuses is listed by Airtable record ID with a short reason and tried again on the next run; the ones that worked are kept.

    4. Links locked

    The second pass: sets each record's link fields to the Planning records its Airtable links became. A link to a record that is not loaded yet waits (it is never guessed) and is filled in by a later run, after the other table's records are loaded. A table with no link fields has nothing to do here.

    5. Verify locked

    Compares the number of records in the saved file, in this tool's registry, with the records pass done and mapped, and the count Workfront reports (one read of one page; no value is kept). Differences are shown as counts only and are never repaired here. This step opens once the records pass is complete; links that wait for other tables do not hold it back.

    6. Reset this table (danger zone) locked

    Deletes every record of this table's record type in the Planning Workspace and clears what this tool remembers about them, so the table can be loaded again from step 3. The record type and its fields stay. A delete cannot be undone. The dry run reads this tool's own counts and sends nothing.
