Core fields in bulk

Create Workfront Core custom fields (parameters) from a CSV. The columns are field_id, name, label, dataType, displayType, description, isRequired, spelled exactly like that. One field_id (an Airtable field ID) may appear on several rows. Every row is checked on upload: names must be unique and free of characters Workfront does not allow, dataType is one of CURC, DATE, NMBR, TEXT and displayType is one of CHCK, TEXT (capitals). One bad row refuses the whole file, and the problems are listed.

Order of work: 1 choose the environment and enter your name, 2 upload the list, 3 CHECK FIELDS (a read-only scan of Workfront for names that already exist), 4 CREATE NEW FIELDS. Creating stays locked until a scan has completed. Each environment is a section of config.json (workfront.core).

⚠ RESET PERMANENTLY DELETES FIELDS FROM WORKFRONT. It deletes every listed field that has a parameterId, including fields that were already in Workfront before this tool touched them, together with any values stored in them. It cannot be undone. Use it to remove fields that were added incorrectly so they can be corrected and created again.

Workflow: upload the fields you added incorrectly, CHECK FIELDS to get their parameterIds, tick the confirmation and RESET. Each field is deleted from the chosen environment and from the crosswalk, top to bottom, stopping at the first error. Fix the CSV (description, dataType and so on), upload it, check, and create the fields again. A new CHECK FIELDS is needed after a reset.
