    This page only shows what the loader has recorded. It never calls Workfront and never shows a record value, a file name or a link: only Airtable and Workfront IDs, statuses, counts and sizes. The loader itself is run from the command line (loader.py records); see the README. A Planning row belongs to a Workspace, and a Core row has none, so leave the Workspace ID empty when you choose a Core environment.

    Where Core objects go

    For each table that lands in Planning plus Core, decide what it becomes in Workfront Core (a project, a request, which is an OPTASK, or a task) and where those objects are created: the parent's object type and its ID. A request normally goes under its Request Queue project. A task goes under a project or another task. A project goes under a program or a portfolio, or under nothing. Every table has its own parent, so these are kept here, never in config.json. Each decision records who, when and why, and the loader will not create Core objects for a table until both are decided.
