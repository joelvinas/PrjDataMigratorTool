    Stage 2 records each form by hand, because Airtable's API does not return form layout or logic. The base's schema must already be ingested in Stage 1, so fields can be chosen from the list.

    A Choose a form

    A form view is recorded under its Airtable view ID. A form with no view gets a key made from its name. The form's table decides which fields can be chosen. Each save creates a new version; earlier versions are never changed.

    B Record the form

    Form contents, in the order they appear

    Add sections, fields, headings, help text, text blocks and hidden or preset fields. Logic can use any field placed earlier on the form, including hidden ones. Text supports bold, italic and links; use the buttons above each text box.

    C Documentation and rebuild report

    The Airtable report is the audit record. A Workfront Planning report shows the same form with each Airtable field replaced by its target field from the field crosswalk, so a person can build the mirror form. It says plainly when a field has no mapping yet.
