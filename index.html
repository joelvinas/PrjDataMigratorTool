    5 Run profiling

    Reads each table page by page (100 records, about 5 requests per second per base). Profiling counts records in memory and discards them. Values are written to disk only if you tick "Also save every record" below (see step 6).

    Attachment files will be downloaded. Each file is saved as <attachment id>.<extension> in ... under <base id>/attachments/, and an index file per table (<table id>.attachments.json) ties each file to its record and field. This is the only step that downloads files, and it can use a lot of disk space and time. Airtable's links expire after a few hours, so this happens in the same pass; a failed file is listed in the index and can be retried by running that table again (files already saved are kept).
    Record data will be written to disk. The same pass that profiles each table also writes every record and every field value to ... (one JSON file per table), so there is no second set of API calls. The values are never put in the database, the logs or this page. Leave this box unticked for a test run that keeps nothing on disk. See step 6.

    Results

    Download results .csv

    One row per field, giving its row count, null count and cardinality (distinct values; a capped value is a lower bound) for every table in the base and table selected above. This is the data-quality summary to share with support or use to plan field mapping. The file name shows your selection, for example Bases_Tables_Profile_<date>.csv for everything. It contains counts only, no record values.

    Null = missing, empty text or empty list. Zero and unchecked boxes count as real values. A cardinality marked "capped" is a lower bound: the field has more distinct values than the cap.

    6 Saved record files

    Files written when "Also save every record to JSON files" is ticked in step 5. One JSON file per table in ..., written to a temporary name and swapped in only when the whole table was read, so a failed table keeps its earlier file. The folder is excluded from Git. These files contain record values: keep them private and delete them when the migration no longer needs them. Attachment links inside the data are temporary links from Airtable and expire after a few hours; the attached files are downloaded only when "Also download the attachment files" was ticked in step 5, into an attachments folder beside the table files.
