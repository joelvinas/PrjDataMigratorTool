    Every decision on this page records who made it, when, and why. Nothing renames a field or table on its own: the tool proposes, a person approves. Enter your initials (or a short name) before approving anything.

    A Rules and presets

    The rules run in a fixed order: table names first, then the table-name swap, character cleanup, leading digits, and last the duplicate check. The Planning name, the Core name and the Core label are configured separately below; by default they behave the same. Switch a step off to see what it does; the count under it is how many names it changes. The checks that keep names safe (special characters, emoji, spaces, length, duplicates) can never be switched off.

    B Import your renamed names

    A CSV with the headers field_id, old_name, new_name, new_label, old_dataType, new_dataType. Rows are matched by Airtable field ID. new_name is checked as both the Planning name and the Core name, new_label as the Core label. A name you have already approved is never overwritten.

    C Table names

    Approve every table name before any field is reviewed: field names that mention a table (lookups, rollups, links) follow the approved table name. A table with no scope decision is undecided, which is different from out; undecided tables are still checked, and out tables are skipped. Use In, Out (a reason is required) or Clear to record the decision, and choose where an in-scope table lands: Workfront Planning only, or Planning plus Core.
